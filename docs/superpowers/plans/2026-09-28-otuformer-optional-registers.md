# OTU-Former Optional Register Tokens Implementation Plan

> **For agentic workers:** Read the linked design first. Use superpowers:executing-plans to implement task by task. Execution is complete for v0.10.0 (all 28 steps checked); checkboxes track execution, not approval -- committing still requires separate operator approval.

**Goal:** Add opt-in `0|4` registers to eligible standard ViTs without losing pretrained weights, resume state, or image-patch boundaries.

**Architecture:** Keep timm's native ViT token insertion and the existing one-pass masked forward. Resolve checkpoint weight source/name first, then validate its layout against an RNG-isolated native encoder before choosing the final encoder; pretraining and fine-tuning use that same contract. Preserve native-register models when the option is `none` and document the deliberate no-CLS and patch-consumer changes.

**Tech Stack:** Python 3.11, PyTorch, timm (verified locally at 1.0.27), Typer/Click, ONNX Runtime, pytest.

**Spec:** `docs/superpowers/specs/2026-09-28-otuformer-optional-registers-design.md`
**Target release:** v0.10.0 — the implementation bumped `pyproject.toml` and `otuformer.__version__` to `0.10.0`, updated `tests/test_version.py`, and documents `--register-tokens` in `README.md` / `README.cn.md` (Task 6).

## Global Constraints

- Explicit pretraining option is `--register-tokens none|0|4` (default `none`); `none` is distinct from explicit `0` and maps to the internal `None`. No flag on fine-tune.
- On an eligible single-CLS unregistered standard timm `VisionTransformer`, `4` adds registers; `none`/`0` preserve zero-register construction. On a CLS-bearing native-register `VisionTransformer`, `none` preserves the native count; explicit `0|4` fails. Both registered paths require the actual class/capabilities, not a `vit_` model-name prefix; the timm 1.0.27 `vit_small_patch16_dinov3.lvd1689m` is `Eva` and remains out of scope. No-CLS/no-register keeps legacy construction only for `none`; no-CLS/native-register fails at every model/checkpoint entry.
- Use the existing successful standard-ViT `timm.create_model` kwargs for both sides of weight migration, changing only `pretrained` and `reg_tokens`. Check exact backbone key/shape deltas and load strictly; do not modify the legacy zero-register initialization path.
- Copy only the newly initialized register token and register positional entries from student to independently initialized teacher. Preserve separate projector initialization, existing patch losses, EMA, AdamW grouping, and `patch_objective` ownership of the mask token.
- Registered resume requires explicit `student` and `teacher` weights and matching `(actual_count, added_count)` plus exact backbone shape before model/optimizer restore; this includes legacy native-register checkpoints. Legacy no-register resume retains its fallback; fine-tune reads `model_state_dict` (the pretrain writer's teacher copy). Read-only and registered checkpoint reconstruction uses `pretrained=False`; preserve the current `pretrained=True` fine-tune construction for legacy zero-register checkpoints, including its existing partial-load behavior.
- Do not add DINOv3/Eva adaptation (including reconstruction of Eva-style registered checkpoints), Gram anchoring, new datasets/experiments, output formats for embedding CSVs, or an additional training stage. Do not commit without fresh approval; the plan's verification commands are future execution steps.

## File Map

- `src/otuformer/training/model.py`: native/added architecture selection, pretrained weight migration, prefix-aware encoder forward.
- `src/otuformer/utils/checkpoint.py`: selected-state register layout and metadata validation; preserve existing read-only backbone mismatch check.
- `src/otuformer/cli/pretrain.py`, `src/otuformer/training/trainer.py`: explicit-option provenance, new/resumed student-teacher construction, metadata, fine-tune checkpoint loading.
- `src/otuformer/cli/finetune.py`: register-layout preflight before output-directory creation/overwrite, reusing the existing `(ValueError, OSError) -> typer.BadParameter` boundary.
- `src/otuformer/embedding/extractor.py`: image-patch selection and attention-pool cache policy.
- `src/otuformer/vision/cam.py`, `src/otuformer/vision/export.py`: reshape and registered reconstruction; export numeric comparison.
- Tests: `tests/training/test_masked_pretrain.py`, `tests/training/test_finetune_provenance.py`, `tests/test_training_model.py`, `tests/test_checkpoint_utils.py`, `tests/test_cli_smoke.py`, `tests/test_extractor.py`, `tests/test_cam.py`, `tests/test_export.py` (extend existing fixtures).

## Review Focus

- A metadata-free checkpoint with `_orig_mod.backbone.reg_token` must fail **before** being inferred as legacy zero registers: Task 2.
- A native-reg model with `none` must resume with its **own** register weights, not randomly initialized added ones: Task 3.
- A registered resume missing `student` but retaining `model_state_dict` must fail, not restore teacher as student: Task 3.
- A no-CLS/no-register legacy checkpoint must include its first patch in top-k/pooling and form a square CAM grid: Task 5.
- A cached attention pool trained with the old patch set must not be silently reused for a registered or no-CLS/no-register backbone: Task 5.
