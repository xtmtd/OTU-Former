# Relational Pretraining Targets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Use subagents only with explicit operator authorization.

**Goal:** Make new `main` pretraining runs start from synchronized student/teacher encoder state and use weak relational teacher views, cross-only global pairing, and a `0.08` → `0.11` teacher temperature schedule, without resynchronizing or replacing old checkpoint recipes on resume.

**Architecture:** Reuse the implemented `PretrainSettings` resolution and single actual-size architecture probe, resolve the relational recipe and ordinary/weak augmentation configs before output setup, and hand both objects to the trainer. Reject marked v2 training states before model probes. Fresh runs strictly copy student encoder state into the teacher; resumes restore the saved pair without copying. The trainer routes the existing EMA teacher's outputs by consumer, writes effective temperatures/ratio into working schedule arguments, and saves the same effective recipe.

**Tech Stack:** Python, Typer/Click, PyTorch, torchvision, pytest, existing OTU-Former checkpoint and CLI schema utilities.

**Spec:** [Relational Pretraining Targets Design](../specs/2026-11-03-relational-pretrain-targets-design.md), including its final preflight/handoff contract. Baseline: `main` at `f959d3b` (package version `0.11.2`; no published tag/release is assumed).

**Implemented prerequisite:** [pretrain preflight consistency plan](2026-11-04-pretrain-preflight-consistency.md) landed in that baseline. Reuse `resolve_pretrain_settings`, `PretrainSettings`, `preflight_pretrain_run`, the one-shot `pretrain_settings` handoff and `_UNSAVED_ARGS`; do not reimplement their native-size, patch or geometry resolution.

**Status:** Plan for audit and approval, not execution authorization. The proposed `0.12.0` version alignment is a separate conditional step below. Do not commit the plan or implementation, push, tag, release, or run research training without separate authorization.

## Global Constraints

- `main` only. No v2 changes, FIFO queue, AdaSim, new SSL method or command, dependency or dependency-floor changes, new model parameters, or change to the weight tensor layout.
- Keep the relational loss formula and batch candidate set, including same-image diagonals; keep local Cartesian pairing, student temperature, loss weights, the warmup-ratio ramp (now `--teacher-temp-warmup-ratio`, default `0.7`) and extension-tail policy. No separate patch or local teacher temperature.
- Preserve ordinary student and patch-teacher views, patch masks/objective formulas, independent iBOT patch-center logic, and the ordinary-view `cosine_similarity` definition. A different shared temperature still changes iBOT targets.
- Fresh runs copy complete encoder state strictly, keeping the student initializer/backbone source and existing iBOT head copying. No initialization flag, DINO head/reinitialization, extra model parameters or new initialization metadata. Resumes never synchronize or reset saved pairs. Reject marked v2 relational/DINO training payloads before probes/output; downstream consumers stay unchanged.
- Keep historical main resume semantics and direct dataset compatibility. Keep English/Chinese docs in sync and skill parameter cards runtime-derived. Do not edit the installed global skill.
- Work in the repository's configured dev environment; commands below use `python -m pytest`. Run focused red/green checks with synthetic fixtures, no pretrained downloads and no real-data experiments. Do not advance past unresolved failures. The change spans one feature: intermediate tasks are review gates, not independently releasable states.

## Review Focus

The recipe resolver also invokes it before target metadata classification; it consumes already-resolved settings but constructs no model. Reuse this one gate, not separate lists; it does not change shared inference/downstream loaders. `_resolve_relational_target_config` is pure: it returns the resolved bundle, effective ratio and warnings without logging or weak-transform derivation. `_resolve_pretrain_recipe` calls it and completes ordinary/weak config derivation/validation from the supplied settings, without model construction. It retains the exact `PretrainSettings` object, not a second patch-config copy; consumers read `recipe.settings.patch_config`. Task 4 keeps the existing one-shot `ns.pretrain_settings` handoff and passes the recipe through keyword-only `pretrain_recipe`. The dataset reads the recipe's validated augmentation configs. The property indexes the required bundle key rather than using `.get()`. No serialized handoff or additional resolution/cache layer is introduced.

## Research Evaluation Boundary

Implementation acceptance is code and synthetic regression verification, not evidence of efficacy or a requirement to run six training arms. If research training is separately authorized, the first comparison has **two arms only: historical target-recipe baseline versus combined new recipe**, with matched budgets/protocol and multiple seeds. The four remaining configurations are optional diagnostics for explaining regressions, removing unnecessary mechanisms or testing contribution claims; select and authorize them only as needed, rather than automatically running all four. The initial two-arm comparison measures the joint target-recipe change and cannot establish each component's contribution.

The relational target diagonal probability/entropy measurement is not produced by any current metric (`teacher_probs` lives only inside `_ssl_loss`, and `assignment_entropy` is an iBOT patch statistic), so this change adds only a synthetic check of the candidate diagonal and the temperature scaling and no production metric; collecting per-arm training-time distributions remains separately authorized research with its own protocol. Matched seeds also do not give matched per-sample ordinary augmentation once weak crops draw from the same random stream, so the six arms compare recipes rather than isolated teacher inputs. Task 4 must parse all six available recipes in the spec, not execute research runs. Keep synthetic initialization/CLI coverage of the optional configurations; making their real-data training optional does not remove engineering regression checks. All six fresh-run arms use fixed same-weight encoder initialization; the historical target-recipe baseline is not a historical-initialization reproduction. No initialization selector or independent-initialization treatment arm is added, so these experiments cannot attribute a gain to synchronization versus the old policy. If separately authorized later, hold data/splits, seeds, initial student/teacher states, student augmentation, optimizer/schedule, loss weights and evaluation fixed across arms; report component losses/gradient observations, target diagonal probability and entropy with effective temperature/source, and retrieval/clustering with false merges/splits where labels permit. Use the specified patch protocols and distinguish iBOT sharpening. If the optional diagnostics are run, the center contrast is conditional on weak targets and the deltas are not additive; even the full set of six configurations does not estimate the pairing-by-temperature interaction. A matched 2×2 requires its own approval.
