# OTU-Former Workflow Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for direct execution, or superpowers:subagent-driven-development only if the operator explicitly chooses delegation. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a portable conversational Skill that reviews every runtime-derived parameter, obtains approval for one analysis at a time, and teaches with all 230 example images.

**Architecture:** Introspect the installed Typer command tree in a package-owned schema module. Reuse lightweight CLI/core constraints for validation, then derive complete cards and argv from the same explicit inputs. A thin read-only Skill adapter and English workflow references guide the agent; neither is an execution service.

**Tech Stack:** Python >=3.11, Typer >=0.12, stdlib JSON/path/subprocess utilities, existing pytest and Hatchling infrastructure. No new runtime dependency, MCP server, plugin subsystem, or agent configuration manager.

**Spec:** [Workflow Skill Design](../specs/2026-09-30-otuformer-workflow-skill-design.md). Also read its linked output-safety, pseudo-feedback, and documentation-conventions designs before implementation.

Date: 2026-09-30
Status: Proposed; plan creation authorized, execution awaiting operator approval.
Target release: v0.11.0, conditional on separate version and licensing approval.
Current package/runtime version: v0.10.1; current license: MIT.

## Global Constraints

- This request authorizes this plan document only. Do not implement, run analyses, install packages/agents, edit versions/licenses/configuration, commit, or tag while writing it.
- Before execution, obtain explicit implementation approval, including the intended test scope. Real analyses, data preparation, installation, overwrite, versions, licensing, commits, and tags retain their independent gates.
- Direct execution is the default. Do not dispatch workers/reviewers without explicit authorization. Create an isolated worktree only if its creation/location is approved; preserve existing changes.
- Parameter fidelity is the primary acceptance criterion: no omitted parameters, invented aliases, guessed defaults, or unsupported choices.
- Use all 230 images by default, not a reduced subset. Keep `examples/` read-only; use approved demo outputs for derived data.
- Only `pretrain` and `finetune` support `--resume`. Every analysis proposal explicitly selects `--out-dir`; doctor/update do not gain output options.
- Showing all defaults does not mean passing all defaults. Preserve omission versus command-line provenance and unresolved inheritance.
- Never invoke analysis callbacks for schema discovery or validation. Do not initialize models/devices or import heavyweight training code in the schema path.
- Keep root version/help/completion controls separate from command callback parameters. Cover the live registry, not `tests/test_docs.py`'s hardcoded `COMMAND_MODULES`.
- The wheel continues to ship package modules only. Keep one canonical `skills/otuformer-workflow/`; do not add repository `.agents/`, `.claude/`, `.opencode/`, or `.pi/` delivery directories, compatibility links, installers, or automatic settings edits.
- Bundle the applicable full `LICENSE.txt` in the Skill and use `license: LICENSE.txt`; do not replace MIT with proposed future terms before licensing approval.
- English developer documents and Skill body; conversations follow the user. Both READMEs carry equivalent installation/Q&A guidance; new `docs/commands/` files require `.cn.md` twins.
- No automatic pipelines, downloads, reruns, pseudo-round loops, progress database, random-weight demonstration checkpoints, or license-enforcement mechanisms.
- Tests of text/JSON are not proof that every agent obeys approval instructions. Never report unavailable CLI integration checks as passed.
