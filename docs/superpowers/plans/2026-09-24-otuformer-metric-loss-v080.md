# OTU-Former v0.8.0 Metric-Loss Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not implement or commit until the user reviews and authorizes execution; do not commit unless explicitly requested.

**Goal:** Add four explicit supervised fine-tuning loss modes while retaining ArcFace as default and preserving checkpoint/resume and raw-CLS extraction behavior.

**Architecture:** Keep loss math in `training/loss.py` and `training/model.py`, CLI validation in `cli/finetune.py`, and optimizer, persistence, loop handling, and diagnostics in `training/trainer.py`. Use a separate diagnostics file rather than changing existing instant/embedding CSV schemas. Experimental splits, calibration, and loss ranking remain external to the CLI.

**Tech Stack:** Python >=3.11, PyTorch >=2.1, Typer >=0.12, pandas >=2.0, pytest >=8.0; no new dependency.

**Spec:** `docs/superpowers/specs/2026-09-24-otuformer-metric-loss-v080-design.md`; general CLI/checkpoint contract: `docs/superpowers/specs/2026-03-29-otuformer-design.md` sections 3.2, 3.3, 4.2, 4.8. The v0.8.0 design takes precedence where the older design says ArcFace only.

## Global Constraints

- Four modes only: `arcface` (default), `supcon`, `subcenter-arcface`, `subcenter-arcface-compact`. No nearest-positive SupCon, morphology oracle, SoftTriple, SSL anchor, sampler, benchmark runner, or new dependency.
- Only species labels enter training. No morphological inference, center pruning, or automatic K selection.
- Preserve ArcFace defaults `s=64.0`, `m=0.5`, fine-tune batch default `32`, raw-CLS `extract` default, cosine/UPGMA workflow, and read-only checkpoint consumers.
- `--checkpoint` initializes a **new** run (retain compatible trained projector, reset classifier/optimizer); `--resume` restores saved loss and optimizer, rejects explicit conflicts. Ref-script training resume remains unsupported.
- New checkpoints retain `model_state_dict`, `loss_state_dict`, `optimizer`, `class_labels`, embedding head, and size/augmentation/freeze metadata. Both version locations advance to `0.8.0` in the release task.
- Held-out raw CLS is the comparison target; training/projector metrics are diagnostic. No biological training or experimental evaluation belongs to this plan.
- **Confirmed first-round exploratory settings:** SupCon temperature `0.07`, compact K default `2` (both Sub-center modes share the 2–8 range), cosine-distance cap fixed at `0.5`, compact weight default `0.1`. K=2 comes from the design; the other three are agreed starting values, not validated optima. Record all effective values. Inspect training stability, compact hinge activation and center distances, then raw-CLS held-out results before changing settings in a later comparison; do not add a first-round parameter grid.

## Review Focus

1. Unknown/inapplicable CLI flags fail before output/log creation (Task 2).
2. Single-class/no-positive SupCon batches skip; a wholly unusable epoch fails without a checkpoint (Tasks 1, 5).
3. Legacy one-group ArcFace resume retains old optimizer decay, while a new run gives normalized prototypes zero decay (Tasks 3, 4).
4. Parameter-free SupCon resumes without `head.weight` and remains readable by raw-CLS extraction (Tasks 4, 5).
5. Permuting manifest rows preserves its hash, but duplicate count and label changes alter it (Task 4).
