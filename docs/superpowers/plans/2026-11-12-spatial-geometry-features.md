## Global Constraints

- Defaults remain embedding output and its old selection/metrics semantics; spatial defaults to `whole-specimen-pad`, final backbone norm on, export L2 off, final complete block. No new meaning for `--token-mode`.
- Spatial image selection: CSV rows/order, otherwise recursive directory keys; COCO attaches only. Artifact selection: CSV stored keys, otherwise index order. Preserve raw strings/explicit metadata; do not export `sample_origin="first_directory"` values or infer groups.
- One forward obtains selected complete-block outputs; no layer fusion. Prefix/register tokens are not pixels. The exact tap is `tokens = backbone.blocks[i](tokens)` before the next block/final norm.
- Geometry uses edge coordinates, x right/y down, source-to-view column-vector maps; `p_B = M_B inverse(M_A) p_A`. Preserve actual image operations, parameters, order, RNG draws and original annotation states.
- COCO adapter `coco-pixel-index-to-edge-v1`: labeled x/y +0.5 internally, subtract on source output; v=0 sentinel unchanged. No guessing or coordinate-convention flag.
- Keep complete FP32 HWC grids. Use design §5.3's pixel arrays `pixel_geometric_coverage`/`pixel_sampling_valid` and patch arrays `geometric_coverage`/`patch_sampling_valid`, with separate `annotation_in_view`; never call these foreground or anatomical homology.
- Per-image uncompressed NPZ default; NPY shards capped at 256 MiB uncompressed payload, with a dedicated shard for one oversized record. Layout changes no logical array identity, ordering or scores.
- Explicit save/open/re-evaluate only. No automatic cache discovery, extraction resume, partial repair, inference on read, original-product mutation or full-resolution mask copies per view.
- Fixed `spatial-geometry-v1`: 12 total views, default at most 100 evaluated images and 64 queries per pair/direction; existing `--seed` default 42; SHA-256 ranking, cosine matching, original-diagonal PCK 0.01/0.02/0.05 and disclosed coverage/denominators. No photometric perturbation or global quality score.
- Spatial ONNX fixes H/W, ordered layers, norm/L2 and weight source; dynamic batch required, validate batches 1 and 2 and every output initially at atol=1e-4/rtol=1e-3. Unsupported or unvalidated is not success. Preserve legacy embedding ONNX behavior.
- Training losses, update/RNG/checkpoint/resume behavior and optional FIFO remain unchanged; default `--relational-queue-size 0` is untouched. No 4.2 split generator or 4.7 objective/head work.
- Core owns behavior and validation; CLI imports no training-heavy modules for discovery/help. Schema version/shape unchanged, no repeating options or new grouping metadata. Resolve explicitness once.
- Preflight before overwrite; protect images/selector/annotations/masks/model/external data/source artifact including symlink dependencies. Publish completion last; retain failure provenance and delete only attempt-owned files.
- New development docs are English-only. Affected README/commands remain bilingual; runtime declarations remain option truth. Paths in the table are relative to `src/otuformer/`. Create `spatial/__init__.py` without eager model/ORT imports. Concrete records below are the interfaces neighboring tasks may rely on:

- `vision.features.LayerSpec(path: str, block_index: int, grid_hw: tuple[int,int], channels: int)` and `FeatureContract(layers: tuple[LayerSpec,...], input_hw: tuple[int,int], patch_hw: tuple[int,int], prefix_tokens: int, norm: str, norm_module: dict | None, l2: bool, epsilon: float, normalization: dict, model_identity: dict)`. Both are frozen records. `norm_module` records the resolved backbone-relative module path and fully qualified Python class (`module.qualname`) when norm is `backbone`, or null for `none`; round-trip this identity in artifacts and ONNX metadata, rather than storing only the option word. `normalization` records input mean/std; `model_identity` records actual architecture, source content identity and resolved weight source, with absolute checkpoint/graph paths kept in run provenance outside the logical identity. Serialize with named sizes/order; reject unexpected fields on read.
- `vision.geometry.GeometryOp(kind: str, params: dict)` and `GeometryTrace(source_wh: tuple[int,int], view_wh: tuple[int,int], operations: tuple[GeometryOp,...], source_to_view: np.ndarray, view_to_source: np.ndarray)` are frozen records; matrices float64 3x3, numeric arrays not embedded in object-dtype archives. Operation kinds are `crop`, `resize`, `pad`, `rotate`, `affine`, `hflip`, `vflip`; params include actual kernel/fill/canvas/rounding needed to replay the preserved image operation. Input normalization is applied once after geometry and recorded separately.
- `spatial.records.SpatialView(image_key: str, view_id: str, role: str, trace: GeometryTrace, features: dict[str,np.ndarray], pixel_geometric_coverage: np.ndarray, pixel_sampling_valid: np.ndarray, geometric_coverage: np.ndarray, patch_sampling_valid: np.ndarray)`; features keyed by layer path, each HWC FP32. Store pixel coverage FP32 `[Hv,Wv]` in `[0,1]` and pixel validity Boolean `[Hv,Wv]` at `trace.view_wh` (the model-input canvas), plus coverage FP32 `[Hg,Wg]` and validity Boolean `[Hg,Wg]` on the common patch grid. Persist all four arrays once per stored view, shared across layers; base/reference aliases share support too. Trace reconstruction is not a substitute for stored pixel arrays. Do not store support at original-image resolution or duplicate it per feature layer. Frozen dataclasses do not imply owned arrays are immutable: writer/reader must prevent mutation aliasing.
- Product manifest schema v1: `schema_version`, `layout`, `feature_contract`, `product_id`, `files`, `index`, `annotations`, `evaluation_plan`. `files` inventories sealed payload/index/annotation/plan files with hash/bytes; reports and logs belong to the later run-envelope artifact list, not this pre-report inventory; logical product ID excludes physical paths/layout/times. `evaluation_plan` uses explicit absent state when not supplied, not an empty fake protocol. Run status belongs to the existing provenance envelope; a reader requires a completed envelope plus manifest/index integrity.
- Per-image view index entries: ordered `image_key`, generated `sample_id` (stable by write-time selected sample index, reused across its views/layouts and preserved during read reorder/subsets), `image_sha256`, original width/height, explicit metadata, `view_id`, role, appearance record `photometric="none"` (input normalization remains separate), serialized geometry/support version and layer payload references. Support references include all four pixel/patch arrays with shape/dtype/semantic role and codec; trace/support version identifies the conservative-resampling-v1 rule, realized source/view sizes, float64 maps and ordered operation parameters (canvas, crop/clipping, fill, kernel/antialias, boundary and rounding). Derived annotation states are reproducible from source records and operations. Keep source annotation IDs/category schema and source visibility. `sample_id` is a generated storage ID, never a biological group.

These are specific version-1 formats, not general infrastructure. Use existing `canonical_json_bytes`, `canonical_digest`, `snapshot_bytes`, `read_verified_bytes` and status/failure helpers rather than duplicating them. Type-only imports may avoid circular dependencies; no runtime cycle from geometry/features back to storage.
