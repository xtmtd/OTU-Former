## 1. Intent and approaches

Add a DINO-style CLS training method while preserving the effective existing relational method. Align the essential distribution-distillation and cross-view mechanisms, without claiming to reproduce the entire DINO recipe or promising better morphological OTU delineation.

Approaches discussed:

1. Replace relational training entirely. Rejected: existing results remain useful and there is no task-specific evidence that DINO is universally better.
2. Reuse the current MLP's unnormalized output as DINO logits. Smaller structural change, but it keeps a custom head and complicates the interpretation of its shared training/extraction output.
3. **Selected:** retain relational as the default; add an optional DINO head with a normalized bottleneck and a separate prototype layer. Export the bottleneck through the existing projector-output option, while training on prototype logits.

Within DINO, keep EMA centering and no KoLeo as the default baseline. Offer Sinkhorn-Knopp (SK) teacher assignments and a KoLeo regularizer as two independent, non-default options. Do not create complete DINOv2/DINOv3 recipe modes or claim that adding these mechanisms reproduces those systems.

The existing global morphological barcode -> distance -> UPGMA -> morphOTU workflow remains the downstream purpose. Prototype indices are not species, anatomical parts, or OTUs. Coordinate development resumes separately from its [temporary notes](2026-10-31-otuformer-coordinate-temporary-design.md); it is not implemented here.

## 2. Confirmed command and method contract

- Add `pretrain --ssl-method relational|dino`. A new run defaults to `relational`.
- Keep `--out-dim`, default 256, as the extractable projector embedding width. In DINO it is the bottleneck width, not prototype count.
- Add `--dino-prototypes`, default 64, independent of `--ibot-prototypes` (existing default 512). Both are adjustable; neither is inferred from image/species/OTU count.
- Add `--dino-centering ema|sinkhorn-knopp`, default `ema`. This selects alternative CLS teacher-target mechanisms, not two stacked centering operations. Fix SK to three iterations in this delivery; no iteration-count option, queue, or cross-batch assignment buffer.
- Add `--koleo-weight`, default 0 (disabled); finite values greater than zero enable KoLeo. No separate enable switch. Sum the two per-crop KoLeo losses as in DINOv2, so the reference weight 0.1 has the same crop-aggregation convention; it remains an experimental starting point, not an automatic default or a validated project recommendation.
- Explicit DINO-only prototype, centering, or KoLeo settings are rejected in relational mode, including explicitly supplied inactive defaults. Omitted inactive defaults have no effect. Both embedding and prototype dimensions must be positive integers; DINO requires at least two prototypes to avoid a degenerate one-category objective. KoLeo weight must be finite and nonnegative.
- Neither method accepts `--disable-cross-view-loss` any more: `0.12.0` removed that switch in favour of `--relational-pairing`, so the relational method no longer keeps the pre-`0.12.0` batch-relative pairing this design was written against. DINO builds its own pairwise targets. See the Status note for the rebase.
- DINO supports all existing, mutually exclusive `--patch-loss` values: `none`, `consistency`, `masked-feature`, `ibot`. Keep existing masking ratios, strategies, and patch semantics.
- Preserve augmentation profiles, orientation policies, global/local crop settings, backbone support, register-token behavior, optimizer family, clipping, LR and EMA schedules. Do not silently activate new augmentation or extend backbone support.
- Do not add a cross-method checkpoint initialization entry point in this delivery. DINO new runs use the existing model/pretrained-weight source; method changes are not resumes.

Validation occurs before output-directory preparation, overwrite, logger creation, or training. Use existing explicit-option tracking and checkpoint preflight patterns. Extend the tracked options to include `out_dim`, `ssl_method`, `disable_cross_view_loss` (already tracked in the current implementation; preserve that entry), `dino_prototypes`, `dino_centering` and `koleo_weight`, so inheritance and applicability checks use actual invocation explicitness, including explicitly supplied values equal to defaults. Fixed head settings below are recorded effective settings, not a new family of command-line options. Validation details, proposed state/identifier layout, diagnostic aggregation and internal API boundaries below are engineering proposals for review, rather than additional operator-confirmed choices.

### 2.1 Shared pretrain controls (2026-11-02 amendment; implemented, acceptance not recorded)

This amendment adds two opt-in experiment controls to `pretrain`, applicable to both `relational` and `dino`; it does not add them to `finetune`. The operator selected a single negative boolean WD flag below. The original amendment authorization covered document changes and restoring the temporary temperature multiplier from 0.3 to its historical 0.7 only. Both controls now exist in the working tree; current audit-driven remediation is explicitly authorized as recorded above. This implementation fact does not establish historical approval or re-certify old test evidence.

| Option | New-run default | Contract |
|---|---|---|
| `--teacher-temp-warmup-ratio` | `0.7` | Finite float in `[0,1]`; the fraction of planned steps used for the existing linear teacher-temperature ramp. This is not LR warmup or teacher-parameter EMA. |
| `--no-norm-bias-weight-decay` | omitted (`False`) | A single negative flag, like `--disable-cross-view-loss`: omitting it preserves uniform `--weight-decay`, and supplying it gives bias and normalization affine parameters WD=0 while other trainable parameters retain `--weight-decay`. The persisted `config.norm_bias_weight_decay` key stays positive (True = uniform decay). |

Keep all other defaults and behavior unchanged, including loss weights, temperature endpoints, constant WD coefficient, LR/EMA schedules, joint clipping scope/threshold, prototype freeze/scale and CSV schemas. DINO K is the one exception: its new-run default moves from 2048 to 64 in this delivery, K stays adjustable with the same `K >= 2` floor, and it remains independent of `--ibot-prototypes` and of image/species/OTU counts. These controls do not select a DINO-only recipe or change relational unless explicitly requested.

**Temperature schedule.** Extend `_build_teacher_temp_schedule(total_iters, teacher_temp_start, teacher_temp_end, warmup_ratio=0.7)` without changing its existing positional arguments or NumPy float32 construction. Set `warmup_iters = int(total_iters * warmup_ratio)`, using truncation of the float product rather than an exact decimal floor; for example, `int(90 * 0.7)` is 62 in the current Python arithmetic. Preserve this historical arithmetic. For zero warmup steps use the final temperature throughout; otherwise retain the existing `linspace(start,end,warmup_iters)` followed by the final-temperature plateau. This deliberately preserves the historical one-step `linspace` behavior. At 5050 steps, ratios 0.7 and 0.3 yield 3535 and 1515 warmup steps, respectively. Ratio 1 uses the full-plan ramp. Do not reinterpret this option as an absolute 30-epoch requirement or retune either SSL objective.

**WD membership.** With the default enabled, retain exactly the existing single optimizer group, parameter membership/order and WD. With the flag disabled, split the existing stable student-side parameter list into decay and no-decay groups, preserving relative order within each group and omitting empty groups. No-decay membership is the union of parameters locally named `bias` and direct affine parameters of recognized normalization modules: `torch.nn.LayerNorm`, `GroupNorm`, `_BatchNorm`, `_InstanceNorm`, and `RMSNorm` when available. This is a module-based policy, not a blanket exemption for every one-dimensional tensor. Cover backbone, projector, applicable patch modules and DINO student prototypes; deduplicate aliases by parameter identity and assign every collected trainable parameter exactly once. Do not exempt positional/register/mask tokens, generic scales or `weight_v` merely because of their name or shape. Fixed DINO `weight_g` stays absent from the optimizer; epoch-zero frozen prototype gradients remain `None`. Do not add separate WD coefficients, a WD schedule or layerwise LR changes.

Optimizer grouping and clipping are independent. Both WD groups use the existing LR schedule and one joint norm/clip over all unique optimizer parameters. Replace first-group-only gradient collection when supporting multiple groups; grouping must not omit no-decay gradients or silently introduce per-group clipping. The default one-group path must retain its numerical behavior.

**Effective settings and recovery.** Persist effective `teacher_temp_warmup_ratio` and `norm_bias_weight_decay` in authoritative checkpoint `config` for both SSL methods, print them in the resolved startup config, and keep requested values/explicitness separate in invocation `args`. They are common settings, not DINO identity markers. Both `_resolve_relational_ssl_config()` and `_resolve_dino_ssl_config()` use `_resolve_common_recipe()`: check key presence, strictly validate the raw recorded ratio and boolean policy before inheritance or explicit-value comparison, then carry the common keys in the existing `ssl_config_effective` dictionary. Do not route these two fields through `_resolve_inherited_ssl_value()`; its permissive `.get()`/equality semantics can hide null or boolean corruption. That helper remains appropriate for existing out_dim/DINO option resolution; do not introduce a second public resolver or internal effective-config slot. Explicitly extend `_ssl_display_config()`'s common-field whitelist and update relational effective-key assertions. CLI/schema/card handling tracks explicitness for the single `--no-norm-bias-weight-decay` flag (no positive spelling and no `secondary_opts` entry), keeping the help readable at normal terminal widths. On resume, omitted values inherit effective saved settings; explicit equal values are allowed, explicit conflicts fail before output preparation/logger creation. Direct trainer callers use the same preflight. A checkpoint lacking both fields uses historical values 0.7/True and the legacy single-group layout for both relational and DINO; emit a historical-assumption warning rather than claim the saved schedule proves them. DINO's strict required-recipe enumeration continues to cover its existing DINO-specific settings and out_dim, not these two common keys, which follow this legacy rule. Handle the missing-both legacy branch before recorded-value inheritance/comparison: use 0.7/True for omitted or explicitly equal values, and reject explicit nondefaults with a legacy-specific error. Never use "the checkpoint records" conflict wording for assumed values, mutate the loaded payload, or silently accept a new value just because the stored key is absent. A temperature error must say: "The checkpoint does not record teacher_temp_warmup_ratio; historical behavior is assumed to be 0.7. Explicit nondefault values are conservatively rejected to avoid changing an unrecorded temperature schedule. Start a new run to use a different ratio." A WD-policy error must say: "The checkpoint does not record norm_bias_weight_decay; historical behavior is assumed to be True. Changing this policy would require an unsupported optimizer-partition conversion. Start a new run to change Norm/bias decay." The temperature restriction is a conservative schedule-recovery policy, not an optimizer-layout constraint. The WD-policy restriction protects saved parameter-partition/moment mapping; do not suggest that group count alone authenticates compatibility. The temporary hard-coded 0.3 experiment is not identifiable from such a checkpoint and cannot be certified for exact continuation. Reject partially recorded, invalid or config/layout-inconsistent new settings instead of guessing from `args` or group count. Do not mutate the input checkpoint to add inferred metadata.

Preserve saved-plan-aware schedules: same-plan resume reconstructs the original absolute temperature schedule using the effective saved ratio without restarting warmup; an allowed extension retains the existing final-temperature continuation and does not apply a new ramp. Keep original-plan metadata distinct from extended progress/current loader length. Restore AdamW state by exact ordered parameter membership within each expected group, validating group count/order, decay/no-decay partition and state IDs/shapes/steps; never remap moments by shape or silently convert a historical one-group checkpoint to two groups on resume. When the reconstructed partition contains a decay group, its authoritative resumed WD coefficient comes from that group in the checkpoint optimizer, not requested `args.weight_decay` or a new config field. A no-decay-only layout has no decay coefficient to reconstruct or compare with the request: restore its sole group's WD=0.0 and describe the requested scalar WD as inapplicable to this layout, never as a restored decay coefficient of 0.0. A no-decay group must record exactly 0.0, and all group WD coefficients must pass finite/nonnegative envelope validation. Preserve existing optimizer-restore semantics: when a decay group exists, a different requested `--weight-decay` does not change saved WD and is not an error; print a clear requested-versus-restored notice after successful `optimizer.load_state_dict()` and before the first training step, reading the actual loaded group, and retain the saved values. An omitted invocation default that differs from saved WD likewise must not look effective in startup output. Do not compare saved decay WD to invocation WD as a corruption check or trust historical args as effective optimizer state. Determine single-group meaning from the effective saved/legacy `norm_bias_weight_decay` policy plus the reconstructed ordered parameter partition, not from group count or WD alone: True uses the historical all-parameter group; False with an empty decay partition uses a no-decay-only group, while False with an empty no-decay partition uses a decay-only group. The historical group may itself have WD=0.0. This differs from conflicts in the two new recipe options, which still fail. No new scalar WD metadata field is introduced. Read-only embedding consumers need no new training state and preserve existing compatibility.

**Evidence and limits.** The operator reports little effect from local weights 0.5/1.5/6 or the temporary 30% temperature warmup. Those new results have not been independently audited here and do not establish that every run needs an absolute 30-epoch ramp. Known limitation: a checkpoint from the temporary hard-coded 0.3 experiment that lacks these fields cannot resume with ratio 0.3 under this contract. Omission warns and uses assumed 0.7 (same-plan schedule reconstruction is not exact continuation of that experiment); explicit 0.3 is rejected with the truthful legacy error. To retain ratio 0.3, start a fresh run with explicit recorded 0.3 after implementation. Accepting the assumed-0.7 resume is an operator choice, not a claim of reproducibility. Existing audits support the core DINO engineering path, not universal performance parity. Relational's explicit sample-similarity objective may align well with retrieval/clustering, but this remains a plausible interpretation rather than an established cause. Neither new control has a performance acceptance threshold.

**Acceptance.** Test both methods, default parity, enabled/disabled WD membership and actual zero-gradient AdamW decay, joint clipping including no-decay parameters, ratio boundaries/nonfinite values, legacy assumptions, explicit conflicts before log/output mutation, exact nondefault save/resume, repeated allowed extensions with changed loader lengths, and generated schema/replay/bilingual documentation. No new analysis, package/version change, commit or release is authorized. Where the original text below requires a single optimizer group or a fixed 70% ramp, this amendment takes precedence only for the explicit nondefault controls; the historical/default path remains unchanged.

## 3. Head and feature contracts

### 3.1 Relational

Preserve the current `ProjectionHead`: three-layer MLP with 2048-wide hidden layers, GELU, and normalized output. Preserve its batch-relative target, default full global Cartesian pairing, optional same-view-only pairing, existing teacher-center behavior, independent student/teacher initialization, and schedules. Do not silently repair or retune this recipe as part of adding DINO.

### 3.2 DINO

The head is:

`backbone CLS h -> Linear(H,2048) -> GELU -> Linear(2048,2048) -> GELU -> Linear(2048,D) -> L2 normalization -> z -> weight-normalized Linear(D,K,bias=False) -> logits`.

Here D is `out_dim`; K is `dino_prototypes`. No batch normalization. The encoder's existing normalized `projector.net` MLP supplies z; the prototype layer belongs to the separate training-only `DINOObjective` described in §6. Only on a fresh DINO run, initialize the student's `projector.net` following the reference DINO head's truncated-normal weights and zero biases, before synchronizing it to the teacher. Do not reinitialize the backbone, any relational projector, or a resumed DINO projector. Use the explicit bias-free `WeightNormLinear` parameterization (`w = g * v / ||v||`) for each prototype layer, with canonical `weight_g`/`weight_v` checkpoint names; initialize scales to one and keep their `requires_grad=False`. New checkpoints record `dino_weight_norm_api="explicit"`; recorded `"legacy"` is also accepted only as the numerically equivalent parameterization with the same keys/forward/gradients, not as permission to migrate a different layout. Do not mix these keys with parametrization API `original0`/`original1` keys or silently migrate between them. Runtime construction no longer calls the deprecated PyTorch weight-norm helper or relies on its cached non-leaf weight. The declared minimum remains PyTorch 2.9 (operator-approved floor revision recorded on 2026-11-01); previously reported checks used 2.9.1 and 2.12.1, not exactly 2.9.0. These reports do not replace fresh version-gate evidence. Record the exact PyTorch version in validation evidence. Before shipping, run the focused prototype construction, forward/backward, fixed-scale EMA and canonical-key/save-load tests on both the declared minimum PyTorch 2.9 and the current validation version. One version's result alone does not establish support at the floor. Retain these checks when changing supported versions. If the explicit prototype canonical-key/shape/fixed-scale/forward/backward contract fails, reject DINO before output mutation with an actionable contract error; relational must remain usable even if the deprecated external helper is absent. The shared effective-SSL resolver owns one DINO-only compatibility-probe function; new-run CLI preflight (alongside `preflight_pretrain_new_run`), resume preflight after recognizing DINO, and direct `run_pretrain` callers all use that same resolver/probe before output mutation. Do not duplicate probe logic between entry points or defer compatibility errors to objective construction. Use `preflight_dino_prototypes(out_dim, prototypes, centering)` to construct an isolated objective with the effective dimensions and validate both independently constructed layers, preserving RNG state. Retain checks on actual training-device layers as a backstop; do not make relational startup depend on DINO prototype construction or deprecated external API availability. Confirm access to authorized minimum/current-version interpreters before implementation begins; an unavailable minimum-version environment is a readiness blocker, not a check to discover only at final delivery. Provisioning a separate environment requires explicit authorization, or the supported range must be separately reviewed. If the minimum-version checks fail, resolve compatibility or separately review the supported range before shipping. API/key migration and dependency-version policy changes require separate review, never a silent fallback or incidental global pin.

Keep the current single pretrain optimizer parameter group: encoder, student prototype direction `weight_v` and applicable patch parameters all belong to it, with `weight_v.requires_grad=True`. Compute `grad_norm` and clipping from that entire group, including prototype gradients after unfreezing; do not add a separate prototype group outside the current first-group-only statistics/clipping path. When the absolute zero-based training epoch index is 0, after backward set the student prototype parameters' `.grad = None` before global gradient clipping and `optimizer.step()`. Judge this by the restored epoch index, not by converting global steps to epochs or counting epochs since resume. Zero tensors are insufficient: AdamW can still decay parameters with zero gradients. Do not temporarily disable `requires_grad` before optimizer collection or omit the layer from optimizer groups. This intentionally excludes frozen-layer gradients from clipping, unlike original DINO's clip-then-clear order; the reference is the source of the freeze policy, not this ordering choice. Never restart freezing on resume or schedule extension. For `--max-epochs 1`, warn that the prototype direction remains frozen throughout that run; do not reject intentional smoke runs.

Construct student and teacher prototype modules independently with identical dimensions and the same explicit weight-normalized parameterization; initialize the teacher via strict `load_state_dict(student_prototypes.state_dict())`. Do not construct the teacher/objective through `copy.deepcopy`; independent construction plus strict state copy pins the canonical contract and avoids the cached non-leaf-weight problem of the former legacy helper. A fresh DINO run also copies corresponding student encoder parameters into the teacher, including any added registers. Teacher parameters require no gradients. After each optimization step, call name-matched EMA for the encoders and separately for the objective's prototype layers, as with the existing independent iBOT heads. The fixed `weight_g` parameters intentionally participate in this name-matched EMA despite `requires_grad=False`: both source and target stay one, while neither scale belongs to the optimizer. Do not add a special EMA exclusion for them. Resume restores both pairs instead of synchronizing them again. During prototype freeze, prototype parameters remain equal because `.grad=None` prevents optimization/decay; the encoder and bottleneck continue to change and need not remain equal.

Expose embedding z and training logits as explicitly different values. Preserve ordinary encoder forward and `PretrainForward.cls` as extractable embeddings. Feed z to the objective's prototype layer without another backbone forward. Both global and local DINO logits use this explicit training-only layer; local training must not feed z directly into a logits loss. Reuse existing unmasked global forwards for CLS and KoLeo, with no additional image forward for these terms. The separate masked global forwards remain patch-only (§5).

For DINO, normalized bottleneck z is the existing `--use-projector-output` result. Final K-dimensional logits and softmax probabilities have no new public extraction switch in this delivery.

### 3.3 Downstream and fine-tuning

- Default `extract` remains backbone CLS for both methods, including fine-tuned checkpoints. A training change may change learned values; it does not change the selected layer.
- Existing relational checkpoints retain their current normalized projection output.
- DINO SSL checkpoints return normalized bottleneck z with `--use-projector-output`; DINO K must never be mistaken for embedding D in extraction, PCA, fine-tuning defaults, or export.
- A new fine-tune run from DINO loads the backbone and installs the existing fresh metric embedding head, just as the current SSL-to-fine-tune path does. Do not inherit the DINO prototype/bottleneck head as the supervised head. Fine-tune resume restores its trained metric head.
- Fine-tune head selection must distinguish source SSL architecture from the target metric architecture. `config.ssl_method`/`config.ssl_head` belong only to SSL payloads, never to fine-tune outputs. Fine-tune outputs record their active metric `config.embedding_head` and, when the source identity is known, separate provenance `config.ssl_source_method`/`config.ssl_source_head`; retain validated source fields on fine-tune resume and re-resolve them for a new pseudo round as specified below, without promoting them to active SSL identity. For example, `embedding_head=arcface_mlp_512` with `ssl_source_method=dino` and `ssl_source_head=dino_mlp_2048` is valid. Here `ssl_source_*` denotes the original SSL lineage, associated with `ssl_initialization_checkpoint_path`/`ssl_initialization_checkpoint_sha256`, not necessarily the checkpoint loaded directly for this invocation. `initialization_checkpoint_sha256` retains the existing meaning of the directly loaded checkpoint (including a resume source); it need not identify the original SSL ancestor. Preserve the actual current pseudo-mode rule: finetune#2 initializes from the original SSL checkpoint, not finetune#1. Historical fine-tune payloads without these provenance fields remain valid. Preserve `_classify_finetune_source()` returning `ssl` and `_select_finetune_embedding_head()` selecting a fresh metric head. Regress SSL-initialization path/SHA provenance, pseudo-source eligibility, and pseudo-round checks requiring the same original SSL checkpoint; a DINO source must not become `head_only`.
- Treat original SSL lineage as recorded only when `ssl_initialization_checkpoint_sha256` contains a valid nonempty SHA-256; neither presence of `ssl_initialization_checkpoint_path` nor a path string alone establishes it. A recorded SHA identifies the ancestor file, not its method/head by itself. Derive a new `ssl_source_*` pair from the recognized original SSL payload, or preserve an already validated pair with that recorded SHA on fine-tune resume. Do not fabricate a pair from a hash alone or force historical ordinary fine-tune resume to reopen its original SSL file. When a historical original SSL payload is recognized as relational under §6.2 rule 1, explicitly write `ssl_source_method=relational` and `ssl_source_head=projection_mlp_2048`; unknown/unrecoverable source identity remains omitted.
- Keep `ssl_source_method`/`ssl_source_head` out of `REQUIRED_PSEUDO_SOURCE_KEYS` and out of the `resolved` experiment-identity mapping passed to `_assert_pseudo_source_identity()`. For new pseudo rounds, existing original-SSL SHA checks remain mandatory; resolve the pair afresh from the original SSL file at the existing CLI payload load before `pseudo_cli_identity()` and output preparation. `prepare_pseudo_round()` only resolves that file's path and verifies its SHA; it does not load the original SSL payload. Reuse the CLI-loaded payload for training, and perform the same cross-check before output mutation for direct `run_finetune()` callers; if finetune#1 has a source pair, cross-check it separately against that resolved identity and reject a contradiction rather than inherit it blindly. Unknown original SSL identity with no source pair in finetune#1 remains valid: retain existing SHA/experiment checks and omit the output pair. If finetune#1 records a pair but the original payload's identity is unknown, reject that unverifiable pair before output mutation. A SHA alone cannot establish method/head. Pseudo resume validates and preserves the optional pair from its own saved config, retaining the SHA anchor; historical absence remains valid. The current resume path does not require or load the original SSL file, so it performs no original-SSL cross-check and adds no read/hash of that file. Preserve existing manifest, accepted-row hash, pseudo-source and round gates. `pseudo_source_checkpoint_sha256` identifies the finetune#1 checkpoint used for pseudo labels, distinct from the original SSL lineage and from this invocation's directly loaded checkpoint; preserve all three SHA roles and existing gates.
- Keep `ArcFaceEmbeddingHead` output unnormalized. ArcFace, sub-center ArcFace, and SupCon already normalize within their losses; changing fine-tune output normalization is outside this work.
- `cluster` keeps cosine and Euclidean-on-L2-normalized-feature behavior. PCA whitening runs before these distance steps, so normalization at arbitrary earlier stages is not claimed equivalent. Cosine and unit-vector Euclidean pair rankings agree, but average linkage and cutoffs need not be identical.
- Do not mix vectors from separately trained heads/models as one common feature space or assume old distance cutoffs transfer unchanged.

## 4. DINO target, pairing, and updates

For each view, compute student logits a_s and teacher logits a_t. Construct teacher probabilities using exactly one mechanism:

- **EMA (default):** `p_t = stop_gradient(softmax((a_t - c) / teacher_temp))`, where c is the center from before the current iteration.
- **Sinkhorn-Knopp (optional):** concatenate both teacher global crops into an N-by-K matrix (N=2B in the current single-process path), apply temperature and three SK iterations, then split the resulting assignments back by view/sample. Do not balance the crops separately or subtract/update an EMA CLS center in this mode.

Both use `log_p_s = log_softmax(a_s / student_temp)` and `CE(s,t) = mean_batch[-sum_K(p_t * log_p_s)]`.

SK treats Q as a positive K-by-N assignment matrix. Normalize its total mass; each iteration normalizes prototype rows to mass 1/K and sample columns to mass 1/N. Multiply by N and transpose to recover per-sample probability vectors. With only three iterations, sample probabilities should sum to one within tolerance, while prototype marginals are approximately balanced; do not require exact marginal equality on arbitrary logits. Compute SK in float32 with stable exponentiation/log-domain normalization and protected denominators; check finite outputs. Never silently fall back to EMA or uniform targets on numerical failure. Stable/log-domain normalization intentionally differs from the reference's direct exponentiation for numerical stability. Verify it against a direct reference on moderate logits using explicit floating-point tolerances, not bitwise equality, and separately test stress cases.

Gate the existing teacher-global preprocessing and center update by method. Relational alone keeps `t_out.cls - teacher.center`, its following normalization, and `_update_teacher_center()`. DINO sends the unmodified normalized `t_out.cls` bottleneck to its prototype layer; it must bypass that whole legacy preprocessing/update path in both EMA and SK modes. Its encoder D-dimensional center buffers stay zero, including after optimization and resume; the optional K-dimensional objective center is updated only by the rule below. Patch center updates are independent and unchanged.

Do not L2-normalize logits, subtract a center from the bottleneck, use batch-instance similarities, or divide the CE by log(K). Compute distributions in float32. Build teacher targets once from cached pre-EMA global outputs and reuse them for every global/local pair in that iteration; do not recompute balancing for each pair.

With two global crops A and B:

- Global DINO loss averages only student A -> teacher B and student B -> teacher A. No global CLS A -> A or B -> B.
- Local loss averages all student-local -> teacher-global pairs. With zero local crops, return zero local contribution without NaNs.
- Preserve `total_base = global_loss + lambda_local * local_loss + lambda_mask * patch_loss_raw`; add `koleo_weight * koleo_loss_raw` only when KoLeo is enabled. Each component averages its own valid positions/pairs; local count does not implicitly change the global/local ratio. Retain existing defaults, including lambda_local=1.5 and lambda_mask=1.0, without claiming they are optimal for the new loss scale.
- Reuse existing temperature options: student defaults to 0.1; teacher rises from 0.04 to 0.07 over the first 70% of planned steps and stays there afterward. Existing same-plan/extended-run schedule rules remain. No DINO-specific temperature-duration option.
- In EMA-centering mode only, update the DINO center by `c_next = 0.9*c + 0.1*mean(a_t)` over raw, detached teacher logits from both global crops and all samples. Update once per completed optimization iteration using cached pre-EMA outputs, after targets have been constructed; apply it for the next iteration. SK has no active historical CLS center.
- Preserve teacher parameter EMA scheduling and update after student optimization in both target modes. Center EMA and teacher parameter EMA are separate mechanisms. If distributed training is supported by the actual execution path, centering/SK statistics must reflect the documented participating sample pool; this work does not introduce distributed support.

`GlobalDistillationLoss` and `LocalToGlobalLoss` in `training/loss.py` currently implement output-distribution CE but are used only by tests, not by pretraining. Reuse/refactor their CE formula into the DINO path with a helper accepting cached detached teacher probabilities, so EMA and SK share one formula without rebuilding targets per pair; adjust their tests/callers as needed. Keep the active relational `_ssl_loss()` batch-similarity formula unchanged.

### 4.1 Optional KoLeo on backbone CLS

For each student global crop separately, take pre-head backbone CLS features h_i for the B input samples and normalize them to u_i. Find each sample's nearest other sample in that crop by maximum cosine similarity (exclude self with an unambiguous diagonal mask). Compute `L_view = -mean_i(log(||u_i-u_nn(i)||_2 + epsilon))`; sum the two global-view losses to obtain `koleo_loss_raw`, matching DINOv2's crop aggregation. This corrects the earlier mean convention: weight 0.1 times a two-crop mean would equal weight 0.05 times the reference sum, not weight 0.2 times that sum. Use float32, protected normalization/distances, and a tested epsilon convention following the reference implementation. Gradients flow through the selected sample pair; nearest-neighbor index selection itself is discrete.

Use features from the existing unmasked student global forward in every patch mode. Do not run another backbone pass, include local crops, apply KoLeo to bottleneck/logits, or concatenate A/B views into the neighbor pool: the latter would explicitly repel two augmentations of the same image. The candidate pool is the current crop's batch, not a newly deduplicated or label-filtered dataset. Repeated image records or near duplicates remain a documented limitation, not an implicit identity/grouping feature. Coincident vectors can produce large but finite positive loss and dominate the summed gradient (and hence the clipped step), shrinking other components' effective step. Joint norm clipping scales the sum without rotating its direction or restoring the relative influence of the other losses.

Weight zero disables neighbor-search computation. If B<2, skip KoLeo, use zero contribution, and record the skip/eligible sample count. Do not silently drop valid but very similar pairs. Loss values may be negative; logging must preserve the sign. No automatic weight selection, extra margin, nearest-neighbor count option, cross-batch queue, or anatomy/species supervision.

### 4.2 Small-dataset interpretation and experiments

Dataset size alone does not select these options. SK balances soft prototype usage, not species frequencies; K>N is supported, but small or homogeneous batches provide limited assignment evidence. Logits/assignment memory grows with K×2B and prototype storage with K×D; valid dimensions do not guarantee that a device has enough memory. A single teacher vector or identical vectors can produce uniform assignments. Two crops of one image are not two independent specimens.

KoLeo encourages spread of the actual CLS space used by default extraction. DINOv2 reports instance-retrieval benefits, which do not establish improved morphOTU grouping: same-species individuals and near duplicates may also be repelled. Treat the weight as an explicit experiment parameter.

Support all four DINO combinations (EMA/SK with KoLeo off/on). Recommend evaluating the default EMA/no-KoLeo baseline first, then changing one factor at a time before combining them. No real-data superiority threshold, mandatory four-way biological benchmark, or automatic method selection is part of engineering acceptance.

## 5. Patch interactions

| Patch mode | DINO combination |
|---|---|
| none | DINO global and optional local CLS only. |
| consistency | Add existing selected visible same-position patch cosine loss. |
| masked-feature | Add existing masked-position teacher feature prediction. |
| ibot | Add existing masked-position patch prototype CE with its own head and center. |

In every patch mode, global/local CLS and global KoLeo use the existing unmasked student views; teacher globals are unmasked. In masked-feature/ibot, the separate masked student global forwards feed only the patch objective. Do not reuse masked CLS for DINO or KoLeo, and do not add a third global forward. This preserves the v0.7.0 contract (§5 and acceptance item 5) and keeps relational/DINO CLS input conditions comparable. The patch same-crop supervision is intentional even though DINO global CLS skips same-crop pairs.

DINO and iBOT prototype counts, weights, target construction, centers and diagnostics remain independent. `--dino-centering sinkhorn-knopp` changes only the CLS target; it does not switch the existing iBOT patch loss to SK. Its patch center still updates normally. KoLeo adds a pre-head CLS regularizer without changing the chosen patch formula. Preserve patch objective state and update rules; this is not an iBOT head redesign or CLS/patch weight sharing project.

## 6. Checkpoints and compatibility

### 6.1 Canonical identity and state ownership

Every new SSL checkpoint records `config.ssl_method`, `config.ssl_head` (`projection_mlp_2048` for relational; `dino_mlp_2048` for DINO) and D=`out_dim`. Only DINO checkpoints additionally record DINO K, `dino_centering`, `koleo_weight` and fixed DINO architecture/stability settings. Relational `config` omits all DINO-exclusive fields (including inactive `null` values), and relational top-level training state omits `dino_objective`; their complete relational identity pair is valid new metadata, not a partial DINO identity. New SSL checkpoints do not declare `config.embedding_head`; that field retains its existing head-only/fine-tune classification role. DINO's extractable projector is the same normalized three-layer MLP layout as the existing projector, while `ssl_head` describes its training role. Fine-tune output records its actual metric `embedding_head` and uses only `ssl_source_method`/`ssl_source_head` for known source SSL provenance, as specified in §3.3. It must omit active `ssl_method`/`ssl_head`, DINO-exclusive active settings and `dino_objective`; source provenance does not require DINO training state.

Omitting inactive DINO config fields is a deliberate exception to existing persisted patch settings such as `ibot_prototypes: null`. A sparse SSL config separates active recipe identity from generic invocation defaults and avoids interpreting inactive DINO options as partial identity. Do not change the existing patch null convention, and do not spread the display projection into checkpoint config.

The field-omission rules above constrain authoritative `config` and top-level training-state keys, not top-level `args`. Preserve `args` as the invocation/namespace record (excluding `resume_state` and the new internal `ssl_config_effective` slot); it may contain inactive DINO defaults and `*_explicit` flags. These invocation values must not determine SSL method/head, centering, KoLeo weight or training-state applicability, and must not be interpreted as partial DINO identity. Resolve those from validated effective config/state. Retain the existing `args` fallback for historical ref-script model-name/embedding-dimension reconstruction; do not extend that fallback to new SSL identity.

Use a training-only `DINOObjective`, parallel to `PatchObjective`, stored at top-level `dino_objective` with these canonical state entries:

- `student_prototypes.weight_g` (K,1), `student_prototypes.weight_v` (K,D).
- `teacher_prototypes.weight_g` (K,1), `teacher_prototypes.weight_v` (K,D).
- `cls_center` (1,K) only for EMA target mode. For SK register it as `None`, omit it from the state dict, and reject an unexpected saved active CLS center on resume.

The complete MLP-plus-prototype head is intentionally split across the inference encoder and training objective; this is an ownership boundary, not a change to the head's computation. The encoders' `student`, `teacher` and teacher inference alias `model_state_dict` contain backbone and normalized bottleneck MLP weights, not prototypes or a K-dimensional center. Preserve their existing D-dimensional `center` buffer for encoder layout compatibility, keep it zero/inactive for DINO, and do not copy the objective's K-dimensional center into it. Preserve relational's current encoder/top-level `center` save and restore behavior. DINO writes no top-level `center`; DINO resume must bypass the legacy `teacher.center.copy_()` branch and restore `dino_objective` strictly. Patch training state remains under `patch_objective`.

Record one initial freeze epoch, fixed prototype scales and three SK iterations when selected. The optimizer includes encoder, student prototype-direction and applicable patch parameters in one stable parameter group and ordering; restore optimizer/schedule/progress/RNG state using existing ownership patterns. SK assignments and KoLeo neighbor indices are ephemeral batch values, not resumable queues or learned states.

The shared checkpoint resolver used by extract, fine-tune, CAM and export must first distinguish active SSL identity from metric-head identity and source provenance. Validate active `ssl_method`/`ssl_head` only for SSL payloads; a new payload combining those active fields with a metric `embedding_head` is contradictory. In fine-tune payloads, validate the actual metric layout using `embedding_head`; `ssl_source_method`/`ssl_source_head` describe initialization only and never select the current head or require DINO objective state. Reject unknown or contradictory active identities and inconsistent source identity pairs, while allowing historical payloads with no source pair. A present `ssl_source_*` pair without a valid nonempty `ssl_initialization_checkpoint_sha256` is contradictory and rejected by shared consumers; do not accept it as unanchored method-only provenance. A historical payload with a valid SSL SHA but no source pair remains valid. The SHA-anchor requirement also applies to the `ssl_source_*` definition in §3.3; it is not an additional pseudo experiment-identity key. Both relational and DINO bottlenecks use a 2048-wide first hidden layer: width alone identifies the extractable MLP layout, not the SSL training method. Validate the complete D-dimensional projector weights and metadata. DINO pretrain resume additionally requires complete, shape-consistent `student`, `teacher` and inference alias `model_state_dict`, each independently checked against effective D/register layout, plus complete `dino_objective` with canonical weight-norm keys and fixed unit scales. A valid teacher does not excuse a missing/damaged student or alias; no inference-alias fallback or zero-register permissive partial loading applies to DINO. Reject missing encoder/projector/backbone parameters and conflicting shapes before output mutation; preserve historical relational permissive rules separately. Read-only consumers never construct the objective and do not require its training-only tensors for embedding extraction, but must reject conflicting identity or embedding dimensions. Keep active SSL identity and optional source identity available separately from inference `embedding_head`; extraction's effective checkpoint provenance records validated `ssl_method`/`ssl_head` and `ssl_source_method`/`ssl_source_head` pairs actually present in payload `config` separately, omitting absent pairs. A historical relational identity inferred under §6.2 is available for compatibility and fine-tune source resolution, but is not emitted as recorded active identity in extraction metadata. A DINO SSL bottleneck still has inference layout `projection_mlp_2048`; that layout name must not erase its active method or label a metric-head descendant as active DINO. New fine-tuning filters training-only state and remains classified as SSL initialization.

### 6.2 Compatibility and inheritance

Compatibility rules:

1. Apply this rule only to SSL payloads, after preserving the existing recognition of fine-tune/metric-head payloads. Metric/legacy markers take precedence: presence of `config.embedding_head`, `config.loss`, or top-level `loss_state_dict`, `class_labels`, `loss_func`, or `model` makes the payload a metric/head-only/legacy candidate, even for a declared `projection_mlp_2048` head or empty loss state. A selected first projector layer of width 512 is also a metric-layout marker. Such payloads have no active SSL identity; contradictory active SSL identity/DINO state is rejected. These markers do not bypass the existing metric validation or make unsupported ref-script files eligible for fine-tuning. Without those markers, a complete recognized 2048-hidden SSL MLP may be historical relational, including ref-script SSL weights whose `args` reconstruct model/D; ref-script `args` without `config` remains unsupported by the fine-tune trainer. An old backbone-only or otherwise indistinguishable payload retains existing permissive inference fallback and trainer eligibility, but has unknown SSL identity rather than fabricated relational provenance. A historical SSL checkpoint without a method field is relational only when its layout is recognized as an existing SSL layout and it has no new DINO markers (`ssl_head=dino_mlp_2048` or `dino_objective`). A partial new identity must fail rather than silently downgrade to relational. Preserve existing legacy readers and warnings. An old checkpoint stripped of all distinguishing new metadata and training state can be indistinguishable from a historical MLP payload; do not claim to recover its lost training provenance.
2. New SSL files record method/head and applicable effective DINO options explicitly; fine-tune files follow the metric-head/source-provenance contract above. Conflicting identities or dimensions fail for every consumer. Fine-tune CLI preflight validates active/source identities on its loaded payload before output preparation or logger creation for ordinary initialization/resume and new/resumed pseudo rounds; direct trainer calls perform the same validation before `mkdir`. Validate the actual `model_state_dict` used by fine-tune against active identity, complete recorded SSL projector layout and dimensions; default teacher selection, zero-register fallback and later metric-head replacement must not mask a conflicting alias. Preserve unknown historical identities as specified in rule 1. Pretrain resume also validates prototype count/state, target mode/center representation and required training states before output mutation.
3. On DINO resume, omitted `out_dim`, prototype count, DINO centering and KoLeo weight inherit saved values; explicit conflicts fail. Omitted `ssl_method` resolves from a recognized checkpoint in either method. Preserve relational's current `out_dim` invocation/default behavior; this delivery does not silently add relational dimension inheritance. A relational resume with an incompatible dimension must fail before output mutation rather than load a mismatched model. Do not switch EMA/SK or change KoLeo weight during resume. Validate positive dimensions, DINO K>=2, known centering enum and finite nonnegative KoLeo weight before construction. Use parameter-source tracking to distinguish explicit values from defaults. Resolve the checkpoint method and effective dimensions during CLI resume preflight, immediately after loading `resume_state` and before `prepare_output_dir`, logger creation or namespace handoff. Pass the invocation's requested `out_dim` and explicitness into preflight, validate its effective value against checkpoint metadata and actual projector shapes, and hand that same resolved value to the trainer through a dedicated `ssl_config_effective` namespace slot. Keep `args.out_dim` and other requested SSL fields unchanged. Add the internal slot after printing requested `Parameters:`, exclude it from serialized invocation `args`, and use it consistently for construction, losses, `SSL config:` and persisted effective `config.out_dim`/SSL settings. Never save requested `args.out_dim` as the effective dimension when DINO inherited a different value. Resolve this slot once per invocation for both new and resumed runs. `run_pretrain` uses an existing `ssl_config_effective` directly without resolving it again; only when the slot is absent (direct callers) does it call the shared resolver/probe, before its first output mutation including `out_dir.mkdir()`. The probe is safe to repeat and preserves RNG state, but repeating it must not change resolved values or substitute a second resolution. A probe constructed solely from the checkpoint's own embedding dimension cannot detect an incompatible invocation. For relational, this is a new early incompatibility check, not a new inheritance rule.
4. Resume restores optimizer, objective-owned active/absent CLS center, teacher/student encoder and prototype states, schedule and patch states. Do not reset the head, resynchronize teacher, restart temperature/LR warmup, or repeat the first-epoch prototype freeze. SK and KoLeo add no historical assignment/neighbor state to restore.
5. Relational resume remains supported with its historical contract. No implicit conversion to DINO, even when the operator supplies new-method options.
6. Read-only consumers load the saved DINO embedding MLP/bottleneck and ignore `dino_objective`, as they ignore training-only patch state. Prototype weights and active CLS center are required by pretrain resume, not inference graphs. A valid embedding-only payload need not contain training objectives.
7. Fine-tune checkpoints are classified by their actual saved metric head. A known source pair is stored as `ssl_source_method`/`ssl_source_head`, retained on fine-tune resume and re-resolved/cross-checked for pseudo rounds according to §3.3, and does not turn the output into DINO logits/bottleneck or constitute partial active SSL identity. Extract/export/CAM and fine-tune resume must accept the valid DINO-source metric-head example in §3.3 without constructing a DINO objective.

The shared loader must validate actual saved layouts rather than use a permissive fallback that changes the model under valid-looking metadata. Do not add a global checkpoint-format/version migration or unrelated schema refactor.
