# OTU-Former Optional Register Tokens — Design

Date: 2026-09-28
Status: Implemented and verified in v0.10.0. Execution plan:
`../plans/2026-09-28-otuformer-optional-registers.md`; committing still requires separate operator approval.

## 1. Purpose and scope

Prepare the existing OTU-Former ViT pipeline for possible future dense morphology work by offering four trainable, non-spatial register tokens as an optional backbone feature. This is an implementation capability, not a claim that registers improve morphology, CAM, clustering, or dense correspondence. The new option accepts `none` (the default), `0` or `4` for eligible one-CLS ViTs. `none` preserves existing construction and legacy checkpoint reading for models with neither CLS nor registers (their current `[:, 0]` result is the first patch, not a CLS embedding); an explicit `0` or `4` is rejected for those models. Their patch consumers **do change**: extractor's hard-coded `[:, 1:]` currently drops the first patch, while `num_prefix_tokens=0` keeps it; old patch-topk embeddings and attention pools should be regenerated. For a square patch grid with at least two patches per side, CAM currently tries to reshape `k²-1` tokens and fails; the corrected zero-prefix reshape makes CAM usable. CLS-free **native-register** models are outside the register-aware CLS contract: new pretraining (even with the default `none`), pretraining resume, fine-tuning, extraction, CAM and ONNX export reject them with a clear no-CLS error. This is a deliberate breaking change: a prior run could treat its first register as CLS. The scanned `runs/` logs and sampled old/current checkpoint metadata name only `vit_tiny_patch16_224`, not `*_gap*`, but this does not rule out external checkpoints. Correcting patch consumers also changes patch-topk/attention-pool outputs for CLS-bearing native-register checkpoints that previously included registers as image patches; regenerate affected derived embeddings or trained attention pools. For a square patch grid, old CAM `[:, 1:]` necessarily fails for four-register models (`k²+4` is not a square for `k>0`); excluding registers fixes that path. For CLS-bearing native-register legacy pretraining checkpoints, resume now requires both `student` and `teacher`; missing teacher state no longer falls back to a fresh model. Fine-tuning a native-register checkpoint now rejects missing or extra backbone keys even though the head-loading path uses `strict=False`. For a changed patch set, an explicitly requested stale attention-pool path can resolve to its compatible policy-specific sibling; the selected path is reported, and neither file is overwritten silently. New pool metadata records `num_prefix_tokens`, `register_tokens`, `prefix_excluded`, and `attention_pooling_type`; `num_prefix_tokens` distinguishes one-CLS/no-register from no-CLS/no-register. ONNX Runtime/PyTorch numeric comparison introduces a new validation failure condition for all exports when the optional runtime is installed.

In scope: the `--register-tokens` option with values `none` (the default), `0` or `4` for previously unregistered standard timm `VisionTransformer` backbones with a single CLS token, while preserving CLS-bearing native-register models at their native count when the value is `none`. New added-register runs start from the usual timm pretrained backbone and use the existing student–teacher pretraining loop; registers are optimized together with the backbone, not in a separate stage. All existing patch-loss modes (`none`, `consistency`, `masked-feature`, `ibot`) remain available without changing their losses or default configuration. The design was checked against the installed timm **1.0.27**; `pyproject.toml` currently says `timm>=1.0`, so implementation must establish an appropriate supported version floor (or explicit capability checks) and test the actual supported version(s), including a registered global/local `forward_pretrain()` shape check for the private `_pos_embed()` behavior, rather than relying only on constructor signature checks.

Out of scope: DINOv3/Eva adaptation (including reconstruction of Eva-style registered checkpoints), a second register-training phase, Gram anchoring, new dense losses or heads, new downstream datasets/experiments, and changes to the roadmap. In installed timm 1.0.27, `vit_small_patch16_dinov3.lvd1689m` is `Eva` despite its `vit_` name and four native registers; its positional-embedding and block-forward contracts differ from the standard ViT pretraining path. The registered paths below require an actual timm `VisionTransformer` (subclasses only when the same checked contract holds), not a `vit_` name prefix. Existing unrelated zero-register checkpoint behavior is not broadened or retroactively restricted by this feature.

## 2. Token and initialization contract

The added-register layouts are `[CLS][PATCH...]` for `0` and `[CLS][REG1–REG4][PATCH...]` for `4`; supported CLS-bearing native-register models retain their own native count. Registers participate in self-attention and contribute to the CLS representation indirectly, but are never interpreted as image patches, spatial locations, masked patch targets, or pooled/top-k patch candidates. Use the backbone's `num_prefix_tokens` consistently when selecting image patches; CLS stays at index zero. The patch grid and mask indices retain their original image-patch coordinates.

Use timm's native `reg_tokens=4` constructor for a standard ViT, rather than hand-inserting tokens into blocks. Do **not** pass `reg_tokens=4, pretrained=True` directly to a model whose published pretrained checkpoint has only one prefix token: its positional embedding has a different shape. For a new registered run, build the original one-CLS timm model with `pretrained=True` and an otherwise identical registered model with `pretrained=False`. Construct the second model with exactly the existing successful standard-ViT constructor kwargs (`img_size`, `num_classes=0`, `global_pool=""`, `dynamic_img_size=True`, and any existing model-specific options), plus only `reg_tokens=4` and `pretrained=False` in place of `pretrained=True`; do not change the `0` path or copy a second set of defaults. Verify `dynamic_img_size=True` and that both models have the same effective patch size/grid. The pretrained model is already sized to the target grid before migration. Compare the two timm **backbone** state dicts, not the outer encoder (`projector`, `center`, and possible `_pretrain_final_norm.*` alias); the registered backbone must have the original keys plus exactly `reg_token`; all shared weights have identical shapes except `pos_embed`, whose length grows by four when `no_embed_class=False`, and whose shape stays unchanged when `no_embed_class=True`. Copy **every** original tensor, not just shape-compatible tensors. When prefix positional entries exist, assemble `[pretrained CLS position | four new register positions | all pretrained patch positions]`; otherwise retain the pretrained patch-only `pos_embed` unchanged. Use the native-initialized register positions (rather than zeroing them), acknowledge that their presence perturbs the initial CLS output, and do not assert that a registered encoder produces the same output as the unregistered encoder. Load the resulting state strictly; reject any other missing key, changed shape, or ambiguous mapping.

Both registered paths require a standard `VisionTransformer` (`isinstance`, with capability/key checks rather than a hard-coded exact class), `has_class_token=True`, `cls_token` present, and `num_prefix_tokens` equal to one plus the actual register count, with no extra prefix/distillation token. The *addition* path further requires `reg_token is None`, `num_prefix_tokens==1`, a learned `pos_embed` tensor, and the exact migration invariants. A hybrid ViT is eligible for addition only if these checks hold. Native `*_reg4_*` is not an addition target; CLS-free `*_gap*` models are not eligible for explicit addition, and DINOv3/Eva remains outside this pretraining design. When the new value is `none` (the default), native-register, CLS-bearing standard ViTs retain timm's existing default construction and native pretrained registers; an explicit `--register-tokens 0` or `4` on such a model is rejected instead of silently replacing/doubling its native registers. Legacy native checkpoints retain native-model construction on resume and in readers, without passing `reg_tokens` again. The existing zero-register path for eligible unregistered backbones otherwise stays unchanged.

The current trainer creates teacher and student **independently** with different RNG seeds (`trainer.py`), not by `deepcopy`; pretrained backbone weights match but newly initialized projectors need not. For a new registered run, initialize the student once, construct the teacher with the same architecture, and copy the student's newly initialized `reg_token` and, if present, its four register positional entries into the teacher **before the first forward/EMA update**. Assert exact equality of those new parameters and of the pretrained backbone weights, without changing the existing independent-projector initialization or requiring entire student/teacher state dicts to match. On registered resume, construct both encoders with `pretrained=False`: added four uses `reg_tokens=4`, native registers use their default architecture (`reg_tokens=None`); load each saved state without migrating from timm weights. Legacy zero-register resume keeps its existing `pretrained=True` construction. The existing name-matched EMA then updates the registers normally. The training-only mask token remains separate.

Both global crops and local crops use timm's `dynamic_img_size=True` positional resampling. The training path already replaces selected **patch embeddings** before `backbone._pos_embed(patches)`; timm inserts CLS and registers in `_pos_embed`. Never flatten or interpolate `pos_embed[:, 1:]` as if it were patch-only for the registered layout. For a crop with `N` patch embeddings, both masked and unmasked forward token sequences have length `N + backbone.num_prefix_tokens` (`N+5` for added four), and masks have length `N` and index only the image grid. Local views currently use the ordinary encoder forward, while masked losses use global views; both routes must include registers.

## 3. CLI and checkpoint contract

Add `--register-tokens` to pretrain, accepting `none`, `0` or `4` (default `none`). Preserve `none` distinctly from explicit `0`: the CLI's `none` maps to the internal `None` and must not be rewritten to `0` before model selection, nor serialized as if explicitly passed. On a **new run**, `none` leaves the model's native construction alone: effective count `0` on eligible unregistered ViTs, or the architecture's native count on a CLS-bearing native-register ViT; no-CLS/no-register models keep their existing construction. Explicit `0|4` applies only to an eligible originally unregistered one-CLS ViT. On **resume**, resolve the model name from checkpoint metadata before constructing either encoder (and reject a conflicting explicit `--model-name`); when old metadata has no model name, use the supplied CLI model name and verify full backbone keys/shapes. Then inherit the saved architecture: legacy native-register checkpoints infer their count from the resolved model's default structure and must match the selected student and teacher tensors; added-register checkpoints use recorded metadata. An explicitly different count fails before loading model/optimizer state, and an explicit flag on a native-register model is rejected even when the numeric counts coincide. Do not add a register-only command, new loss flag, or independent training stage.

Save the **actual** `register_tokens` count in pretraining checkpoint `config` and carry it into subsequent fine-tuning checkpoints; the resolved timm model's native architecture determines whether that count is native or added. Read recorded register count only from `config.register_tokens`, never from `args.register_tokens`: the latter records the current invocation's `none`/`0`/`4` (as `null`/`0`/`4`) and may be `null` even when the saved architecture has registers. For legacy checkpoints with no recorded count, infer only from the native architecture and selected weight tensors as specified below. If a future timm version changes that default, the model/count/weight checks fail rather than guessing a new reconstruction. Resolve the weight source first: read-only defaults to `teacher`, then `model_state_dict`, `model`, `student` (optionally preferring student); fine-tuning reads `model_state_dict` even when its source is an SSL checkpoint (the existing pretrain writer stores a copy of **teacher** there); legacy no-register pretraining resume reads `student` or falls back to `model_state_dict`, plus `teacher` when available; registered resume requires explicit `student` and `teacher` as specified below. Inspect/validate the actual selected state, not another field. The training-only mask token is saved under top-level `patch_objective`, never `backbone.*`. Inside each encoder state dict the canonical register key is `backbone.reg_token` (`student` is a top-level checkpoint field). **Before** deciding whether the state has registers or is legacy `0`, reject any key ending in `reg_token` that is not exactly `backbone.reg_token`, including `module.backbone.reg_token` and `_orig_mod.backbone.reg_token`; do not allow a prefixed registered checkpoint to fall into the zero-register path. The existing resolver renames legacy projector keys but does not normalize these wrappers. Do not impose a blanket unknown-namespace rejection on old checkpoints: sampled recent ones include `_pretrain_final_norm.*` aliases alongside `backbone.*`, `projector.*`, and `center`. `_pretrain_final_norm` is an alias of `backbone.norm` (same module and parameters), not a separately initialized copy.

Reconstruct deterministically from the resolved model name and saved image size. First inspect keys for noncanonical `reg_token` suffixes, then probe the model with its **native** timm options and `pretrained=False` without advancing the caller's RNG state; inspect its actual class before reading ViT-specific attributes (reject non-`VisionTransformer` registered paths even if their names start with `vit_`), class token, native register count, and expected state-dict keys. This probe does not replace the existing `pretrained=True` final construction for legacy zero-register fine-tuning, whose permissive partial-load behavior stays unchanged. If this CLS-bearing architecture natively has registers, do not add any: absent metadata is allowed only for legacy checkpoints whose selected weights exactly match the native backbone; recorded count must equal the native count (which need not be `4`). If it natively has none, only `0` or `4` is valid: absent count with no register tensor means legacy `0`; absent count with one is rejected; recorded `0` requires no register tensor; recorded `4` requires `(1, 4, D)` and reconstructs with `reg_tokens=4`. Any conflict, missing tensor, extra backbone tensor, unexpected prefix, or shape mismatch fails **before** `load_state_dict`. Require a single CLS token for the new addition and supported native-register paths; no-CLS/no-register legacy loads and omitted-flag runs keep existing construction and first-token semantics outside those paths, while patch extraction and CAM slicing change as stated in Section 1.

| Native count with CLS | Recorded count | Selected register tensor | Decision |
| --- | --- | --- | --- |
| `0` | absent or `0` | absent | Rebuild without additions (legacy or new zero-register checkpoint). |
| `0` | absent or `0` | present | Reject. |
| `0` | `4` | `(1, 4, D)` | Rebuild with four added registers; check all backbone shapes. |
| `0` | `4` | absent or malformed | Reject. |
| positive | absent (legacy) or equal to native count | matches native shape | Use default native model, with no addition. |
| positive | different from native count | any | Reject. |
| positive | absent or equal | missing or malformed | Reject. |
| any CLS model | other unsupported value for that architecture | any | Reject. |
| no CLS, native count `0` | absent or `0` | absent | Legacy reconstruction; retain the old first-patch-as-CLS semantics, but correct patch/CAM slicing to zero prefix. New checkpoints record `register_tokens: 0`. |
| no CLS, native count `0` | other recorded value or any register tensor | any | Reject. |
| no CLS, native count positive | any (including absent) | any | Reject at all checkpoint entry points: this model lacks a CLS token. |

For an added-register model with `N` saved-size patches, `pos_embed` length is `N+5`, or `N` when `no_embed_class=True`; the reconstructed model's full-backbone key/shape check is authoritative for both this and native variants. A checkpoint without a recorded model name can use the caller's model-name fallback (including the CLI default) only if its complete backbone matches; otherwise require the correct model name. Registered pretraining resume (added registers **or CLS-bearing native registers**, including legacy native checkpoints) must require explicit `student` and `teacher` encoder states, validate their complete backbone keys/shapes **before** applying either state or optimizer, and reject either missing field explicitly. A legacy zero-register resume is excluded from this requirement: it retains the existing `student` then `model_state_dict` fallback and does not require `teacher`. For registered resume, if `model_state_dict` is also present, validate its register layout and all `backbone.*` keys/shapes against the same resolved architecture; it remains the teacher-copy source for downstream consumers. Do not apply this new complete-backbone requirement to legacy zero-register resume. `center` and `_pretrain_final_norm.*` are not backbone keys, so they must not fail this check. Do not require byte-for-byte equality with `teacher`. The legacy `model_state_dict` fallback is a teacher copy, not a student replacement; constructing a random teacher or copying the student would not restore the saved EMA. This is stricter than the legacy no-register resume path, which stays unchanged. Resume with a different architecture/count is prohibited. For added/native-register fine-tuning, reject missing or unexpected `backbone.*` keys even with `strict=False`, naming representative keys in the error; keep existing projector/head replacement rules. Do not broaden this new fine-tune rejection to all legacy zero-register training checkpoints: sampled `runs/old/pretrain`, `runs/pretrain`, `runs/arcface/pretrain`, and `runs/old/finetune` checkpoints have exact backbone key/shape matches to the installed timm 1.0.27 model, but older external timm versions are unverified. Existing read-only `_reject_backbone_mismatch` already rejects missing/extra/shape-mismatched `backbone.*` keys; use it instead of duplicating the check.

For read-only consumers, `resolve_checkpoint()` first selects the weights and model name without constructing a model. A shared read-only loading path then scans the selected state for noncanonical keys, constructs an RNG-isolated native `pretrained=False` encoder at the saved image size, and resolves the layout against it. Reuse that encoder for native or zero registers; build an added-four encoder only when needed. The resulting `CheckpointArchitecture` carries actual and added register counts alongside the selected weights, so extract, CAM, and export load the same verified layout without each inventing a reconstruction order. Fine-tuning and pretraining resume use the same layout validation with their stage-specific weight sources; legacy zero-register fine-tuning and pretraining resume retain their existing `pretrained=True` construction. Embedding extraction, CAM, and ONNX export rebuild with `pretrained=False` and check complete backbone weights. Fine-tuning has **no new `--register-tokens` switch**: the existing CLI requires a source `--checkpoint` or `--resume`; it inherits the source architecture and does not introduce a direct-from-timm mode. It resaves the actual count for native or added models. Never initialize an unmatched register from timm while loading a saved checkpoint.

## 4. Consumer changes

- `training/model.py`: accept `0|4` for eligible models, apply the explicit weight-migration invariants, and exclude all prefix tokens when returning patches. Keep `forward_pretrain()`'s `patch_embed` → optional patch-only mask replacement → backbone `_pos_embed()` flow; test both global and local sizes.
- `training/trainer.py` and `cli/pretrain.py`: resolve/save/validate the option; synchronize the new student/teacher parameters at initialization; preserve the existing patch-objective `num_prefix_tokens` slicing and named EMA. Current pretrain AdamW places `cls_token`, `reg_token`, and all other trainable student weights in one group with the same LR/weight decay; neither timm's `no_weight_decay()` nor `group_matcher()` is used. In installed timm 1.0.27, those timm helpers do **not** include `reg_token`, so any later switch to timm optimizer grouping would require a separate review. Keep this established policy rather than introducing token-only groups or layer-wise decay.
- Fine-tuning in `cli/finetune.py` and `training/trainer.py`: run register-layout/source validation in the existing pre-output `try` block before `prepare_output_dir`, so `--overwrite` cannot delete an existing output before rejecting a broken registered source; reuse the existing `ValueError`/`OSError` to `typer.BadParameter` boundary, with a narrow wrapper for damaged checkpoint loads. Inherit architecture from the checkpoint, propagate count to saved metadata, and leave its existing CLS → projector embedding/head behavior unchanged; there is no custom average-pooling path. Fine-tune optimizers place register and CLS in the backbone group with the same LR/decay; `freeze_ratio` freezes only early Transformer blocks, not either prefix parameter. The saved register count also joins the v0.9.0 pseudo-label experiment identity (`DERIVED_IDENTITY_KEYS`, resolved from the initialized source), because two runs can agree on every other identity value while training on different token sets; a pre-v0.10.0 source records no such key and is therefore not compared.
- `utils/checkpoint.py`: resolve the count from selected weights and metadata according to the decision table, then rebuild readers without weakening existing backbone-mismatch checks; keep legacy no-register behavior and recognize existing `_pretrain_final_norm.*` alias weights as non-backbone.
- `embedding/extractor.py`: exclude all prefix tokens in attention-query training and both directory/CSV patch-topk and attention-pool extraction. The existing top-k uses **patch-feature norms**, and its attention pooling computes weights only after receiving patch features: it does not read a backbone CLS→patch attention matrix. Assert the selected candidates/attention keys contain image patches only. The separately saved attention-pool checkpoint already has an `args` payload: for newly trained pools, record `num_prefix_tokens`, the actual register count, `prefix_excluded=True`, and `attention_pooling_type`; prefix count distinguishes one-CLS/no-register from no-CLS/no-register. For backbones whose patch set changes (registered models and no-CLS/no-register models), do not silently reuse an old attention-pool checkpoint missing this policy or recording a different one; a missing policy counts as compatible only for a one-prefix, zero-register backbone. Derive a policy-specific sibling filename from the requested/default path using `num_prefix_tokens`, register count, and pooling type; validate the stored policy even when its filename matches. Retrain there from the training CSV if absent, without overwriting an incompatible existing file, or report that the CSV is needed. Later extractions must discover the same sibling automatically. Keep existing one-CLS/no-register legacy pools readable. Embedding CSVs currently contain IDs and vector columns, not a model-config sidecar; do not add a new output format solely for this feature. If a future consumer reads a full backbone attention matrix, slice its **key** dimension at `num_prefix_tokens` after any all-token attention computation; do not add a speculative rollout implementation now. CLS and projector outputs keep their current semantics.
- `vision/cam.py`: bind the loaded backbone's prefix count to ViT reshape so only image patches form the heatmap grid. Current CAM methods are GradCAM, GradCAM++, LayerCAM, AblationCAM, ScoreCAM, and EigenCAM; there is no attention rollout. Keep the square-grid constraint and test applicable methods on registered models rather than treating register activations as image pixels.
- `vision/export.py`: reconstruct the correct architecture; ONNX exports the encoder's existing embedding output with dynamic **batch** only (not dynamic image resolution). The current ONNX Runtime check verifies output shape; when ONNX Runtime is available, compute the `eval()` PyTorch reference on **CPU FP32** using the same dummy input as CPU ONNX Runtime and compare at the chosen export size for **all** checkpoints (`atol=1e-4`, `rtol=1e-3` as initial thresholds), and fail on a numeric mismatch rather than reporting shape-only validation. Here `validated=True` means CPU ONNX Runtime output has the expected shape and agrees numerically with CPU FP32 PyTorch within the approved tolerances. Published reports include machine-readable `validation_status="passed"` with `validated=True` after numeric agreement, or `validation_status="skipped"` with `validated=False` when ONNX Runtime is not installed; `validated` remains the backward-compatible boolean. Runtime execution errors and numeric mismatches when ONNX Runtime is installed raise without publishing a model or report for this attempt. Export and validate using temporary `.onnx` and external-data paths; on validation failure clean up only this attempt's temporary files, leaving prior published output and report intact. After validation, before replacing the output atomically write `validated=False`, `validation_status="invalidated"`, the final path, and a publication-in-progress reason to invalidate any old success report; then publish the new output and its matching `passed`/`skipped` report. A publication failure can leave the old or new model alongside this `invalidated` report, never a stale `validated=True` report. `export_report.json` is directory-scoped, so this existing format can invalidate another export in the same directory. Record the measured `max_abs_diff`, actual `atol`/`rtol`, and register count in the existing `export_report.json`, not a new metadata format.

Before implementation, search all in-scope production Python paths for hard-coded first-token slicing, `num_patches + 1`, manual prefix interpolation, and attention-key selection. Keep legitimate CLS-at-zero uses; fix only assumptions that treat registers as image patches. No DDP-specific change is needed: this project does not currently wrap this pretraining loop in DDP.

## 5. Verification and acceptance

Automated tests, not new downstream experiments, must establish: eligible `0` preserves old CLI/checkpoint behavior; migration meets the exact key/shape difference rules and preserves pretrained CLS/patch/block weights and positions; new student/teacher register parameters (and their positional entries, if present) start equal while existing projector initialization behavior is preserved. The migration's added-register model construction advances RNG, so equal user seeds do not imply identical projector initialization across `0` and `4` runs; the native-architecture probe must preserve RNG state. Test migration with a small synthetic ViT and locally supplied pretrained state dict (no network required); a real timm weight download is optional integration verification. Test `no_embed_class=True` explicitly: `pos_embed` shape does not reveal register mismatch, so the register key and metadata checks must run before any non-strict load.

In `eval()` (to avoid dropout/drop-path/patch-drop randomness), registered unmasked global `forward_pretrain()` must agree with backbone `forward_features()` and produce `N + backbone.num_prefix_tokens` tokens (`N+5` for added four); test the ordinary encoder at local-crop size for dynamic resampling. A masked global forward must preserve the same length, mask only patches, and give nonzero `reg_token.grad` for a deterministic patch-output loss. Check all patch loss modes and the current optimizer group. Exercise every applicable checkpoint-table row on the selected source, both pretraining resume states (plus a present `model_state_dict`), and fine-tune source/resume; cover `none` native CLS reg4 new pretraining, its save/read/resume/fine-tune path, legacy native resume, missing-teacher rejection on registered resume, and `none` versus explicit `0` across saved CLI args and reload. Use a small patched timm factory for a CLS-bearing native count other than `4` if no installed model provides one; do not require a network download. Explicit flags on native models fail; CLS-free native-reg models fail with a no-CLS error at new pretraining (including the default `none`), resume, fine-tune, extraction, CAM, and ONNX export. Use synthetic high-register-norm tokens to show patch-topk and attention pooling exclude them; reject reuse of old attention pools when the patch set changes, including a no-CLS/no-register model. Verify CAM reshape for a no-CLS/no-register model and registered models, including an applicable AblationCAM case, and ONNX Runtime/PyTorch numerical agreement at export size when available. Check an old checkpoint without register metadata and a small registered checkpoint. Test no-CLS/no-register omission versus explicit flag and first-patch inclusion, synthetic no-name checkpoint resume via CLI name, noncanonical `reg_token` suffix rejection before count inference, and the live encoder's `_pretrain_final_norm is backbone.norm` alias (loaded state-dict tensors need only match numerically, not by object identity). Run relevant tests and then the full project test suite before claiming implementation complete.

Success here means an opt-in, recoverable, end-to-end usable standard-ViT register configuration, **not** measured dense-morphology benefit. The accompanying implementation plan is executed (28/28 steps) and this design is implemented and verified in v0.10.0; committing still requires separate operator approval.
